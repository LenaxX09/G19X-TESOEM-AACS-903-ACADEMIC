SECCIÓN 5 · ARQUITECTURA Y DECISIONES IMPORTANTES
────────────────────────────────────────────────────────────────────────────────

  Flujo objetivo (MVP):
    [App Android] --foto Base64--> [API PHP] --> [MySQL]
                                        |--(S3)--> Python OCR (texto → JSON)
                                        |--(S3)--> C riesgo (porcentaje)
                                        |--(S3)--> Prolog (APROBADA/DISCREPANCIA)
    [App Android] <--estado final-- [PHP actualiza MySQL]

  Decisiones tomadas:
    - Envío de imagen en Base64 JSON (RF-M4 simplificado; multipart → v1.1).
    - Estados de factura: Pendiente / Aprobada / Con Discrepancia.
    - UMBRAL_RIESGO = 40 % (riesgo < 40 ⇒ aprobable) — configurable en
      api/config.php.
    - Contratos de los motores FIJADOS ANTES de programarlos (principio
      contract-first, MVP §6.4):
        Python (stdout 1 línea): {"proveedor":"...","fecha":"YYYY-MM-DD",
                                 "monto":1234.56,"folio":"..."}
        C (stdout 1 línea):      37.5        ← % de riesgo
        Prolog (stdout 1 línea): APROBADA  ó  DISCREPANCIA:<motivo>
    - Si un motor falla, la factura NO se pierde: queda "Pendiente" (RNF-5).
    - Seguridad R3/RM4: al llegar S4, cast numérico y saneo de todo lo que
      pase a shell_exec (usar escapeshellarg, nunca texto directo).
    - MySQL: SIEMPRE el de Laragon; servicios MySQL8x de Windows en Manual.

  ★ SPRINT 4 — "INTEGRACIÓN Y DEMO" (PHP orquesta los 3 motores)

    Los 3 motores YA existen, cumplen sus contratos §6.4 y la cadena completa
    funciona por CLI (C3 ✔). Ahora hay que automatizarla y mostrarla:

    1) API: procesar la factura tras recibirla (extender facturas.php o crear
       api/procesar.php). Cadena a ejecutar:
         a) OCR ....... "PYTHON_BIN" RUTA_MOTOR_OCR <ruta_imagen>
                        → JSON {proveedor, fecha, monto, folio}
         b) Riesgo .... RUTA_BIN_RIESGO <monto> <promedio_historial>
                        (promedio ya lo devuelve ordenes.php?id=)
         c) Conciliar . "SWIPL_BIN" RUTA_REGLA_PROLOG <orden_id> <folio>
                        <monto> <fecha> <proveedor> <riesgo> <monto_aut>
                        <proveedor_orden> <fecha_orden>
                        → APROBADA | DISCREPANCIA:<motivo>
         d) UPDATE facturas (estado, motivo, folio, monto, proveedor_detectado,
                        fecha_documento, riesgo, procesado_en=NOW()) → KPI-1
    2) SEGURIDAD (R3/RM4): escapeshellarg en TODOS los argumentos; rutas de
       binarios entre comillas dobles (tienen espacios); cast numérico de
       montos/riesgo; si un motor falla → factura queda "Pendiente" (RNF-5).
    3) App Android: pantalla LISTA (GET facturas.php ya lo da todo): renglones
       con badges ✅ Aprobada / ⚠️ Con Discrepancia / ⏳ Pendiente.
    4) CHECKPOINT C4: demo completa con el guion §9.2 (A aprobada, B excede,
       C proveedor distinto) vista en el móvil.

    Nota: el .exe NO está en git (motores/.gitignore) — si se clona el repo,
    recompilar con GCC_BIN: gcc -O2 -Wall -o clasificador_riesgo.exe *.c
